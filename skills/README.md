# Skills：技能导读

[English](README.en.md) · 中文

你点进这个目录，大概是想知道这 17 个技能各自能做什么。这份导读就是为此写的：**不安装也能当作论文写作的检查清单来读；安装为 Agent Skills 之后，也知道什么时候用、用哪一个、用完接哪一个。**

## 这份导读在项目里的位置

| 入口 | 读者 | 作用 |
|---|---|---|
| 顶层 [README.md](../README.md) | 第一次打开项目的人 | 为什么做、有哪些技能、怎么安装、知识从哪里来 |
| [handbook/](../handbook/) | 想系统了解方法的人 | 论文逻辑、蒸馏协议、写作架构三章 |
| **本文件** | 想直接上手的人 | 17 个技能**分别是什么、什么时候用、怎么接龙** |
| 各目录的 `SKILL.md` | Agent / 大模型 | 可执行规范：步骤、闸门、交付格式（写给机器看，人读起来略硬） |
| 各目录的 `references/` | Agent 按需加载 | 检查卡、矩阵、缺陷编码、镜头卡等细节 |

一句话：**handbook 讲道理，SKILL.md 干活，本导读把两者接起来。**

## 三条主线

17 个技能不是一堆孤立的工具，它们对应中文公共管理论文从选题到退修的完整过程。先用 `pa-router` 判断自己在写哪类论文、卡在哪里，再从对应位置进入。

### 主线一：实证论文（机制解释、案例研究、效果检验）

1. **[pa-question-framer](pa-question-framer/SKILL.md)**：先把主题变成有困惑、有竞争解释的问题
2. **[pa-literature-mapper](pa-literature-mapper/SKILL.md)**：把文献压成解释地图，找到精确缺口
3. **[pa-concept-mechanism-builder](pa-concept-mechanism-builder/SKILL.md)**：写清概念边界与机制箭头
4. **[pa-research-design](pa-research-design/SKILL.md)**：让材料真的能区分你的解释与竞争解释
5. **[pa-paper-architect](pa-paper-architect/SKILL.md)**：按体裁搭全文骨架，定下每一节回答什么
6. **[pa-intro-drafter](pa-intro-drafter/SKILL.md)** 与 **[pa-section-writer](pa-section-writer/SKILL.md)**：写引言与正文
7. **[pa-title-abstract](pa-title-abstract/SKILL.md)**：定题目、摘要、关键词
8. **[pa-prose-polisher](pa-prose-polisher/SKILL.md)**：语言润色
9. **[pa-paper-reviewer](pa-paper-reviewer/SKILL.md)** 与 **[pa-supervisor-panel](pa-supervisor-panel/SKILL.md)**：投稿前审稿与多镜头会诊

### 主线二：概念与理论论文（概念构造、理论适用、规范论证、综述）

`pa-question-framer` → `pa-concept-mechanism-builder`（概念分支）或 **[pa-theory-localizer](pa-theory-localizer/SKILL.md)** → `pa-paper-architect`（选择概念构造、理论适用、规范论证或文献综述的骨架）→ 写作与审稿同主线一。规范论文不强加经验谜题，综述不强加因果机制，这一点每个技能都会遵守。

### 主线三：投稿之后

**[pa-journal-fit](pa-journal-fit/SKILL.md)**（选刊与投稿规范）→ **[pa-revision-responder](pa-revision-responder/SKILL.md)**（退修计划与逐条回复）。

**两个横向技能**，和上面的顺序正交，不是其中某一步：

- **[pa-argument-architect](pa-argument-architect/SKILL.md)**：任何时候觉得「因果讲不清」「这一节为什么放在这里说不出来」，都可以用它把因果链与论证链拆开，逐层检查。
- **[pa-scholar-distiller](pa-scholar-distiller/SKILL.md)**：给维护者和研究者用，从论文或导师批注中蒸馏研究动作；日常写论文不需要它。

## 已经卡在某一环？

遇到具体瓶颈，跳过顺序，直接用对应技能：

- 不知道这个题能不能写、先做什么 → **pa-router**
- 有题目没问题、问题意识不强 → **pa-question-framer**
- 综述像在堆作者，缺口只会写「研究较少」 → **pa-literature-mapper**
- 提了个新概念，审稿人说是「换名」 → **pa-concept-mechanism-builder**
- 「西方理论 + 中国案例」，说不清改了理论什么 → **pa-theory-localizer**
- 案例选择只会写「具有典型性」，或担心识别问题 → **pa-research-design**
- 材料都有了，不知道全文怎么排、每节写什么 → **pa-paper-architect**
- 因果链有跳步，或段落之间接不上 → **pa-argument-architect**
- 引言写成了政策背景介绍 → **pa-intro-drafter**
- 某一节写不出来，或写成了编年史、回归表复述 → **pa-section-writer**
- 题目太长太空，摘要写成了「具有重要意义」 → **pa-title-abstract**
- 公文腔、AI 腔重，长句逻辑断裂 → **pa-prose-polisher**
- 投稿前心里没底 → **pa-paper-reviewer**
- 想要几个不同视角的深度诊断 → **pa-supervisor-panel**
- 不知道投哪本刊，或要对照投稿要求 → **pa-journal-fit**
- 收到退修意见，不知道怎么改、怎么回 → **pa-revision-responder**

## 17 张技能卡片

每张卡把 SKILL.md 的规定翻译成人话，并注明对应的 handbook 章节与上下游技能。

### pa-router：先判断，再动手

- **定位**：识别论文的主贡献载体（制度逻辑与机制解释、概念与理论构造、政策过程与实证检验、改革与政策设计、理论适用性、规范理论、综述与学科反思）和当前瓶颈。
- **什么时候触发**：拿到一个选题、摘要或草稿，想知道它是哪类论文、写作路线怎么走、下一步该做什么。
- **关键纪律**：只推荐最先要解决的瓶颈，不把所有技能依次跑一遍；明确的局部编辑直接交给对应技能，不扩成全文审查；不因为题材新或数据多就判定有贡献；材料不全时先给暂定判断，并说明哪项信息会改变路线。
- **产出**：主类型（必要时加一个次类型）、承重判断、至多三个结构风险、首选的下一步。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **下游**：按瓶颈路由到其余任一技能。

### pa-question-framer：从主题到研究问题

- **定位**：把政策主题、治理现象或数据集转成一个有证据入口、有竞争解释的研究问题。
- **什么时候触发**：只有一个选题方向；审稿人说「问题意识不强」；手上有数据但不知道能回答什么理论问题。
- **关键纪律**：现象用不带价值结论的话描述；反常本身也要核实，不用刻意简化的理论制造冲突；没有文献依据时写「暂定解释」，不虚构出处；规范研究讲价值冲突与理由，不强加经验谜题；「X 是否影响 Y」可以是有效问题，但要讲清估计对象与知识增量。
- **产出**：现象 → 预期及依据 → 困惑 → 主研究问题 → 理论对象 → 至少两个竞争解释及区分证据 → 最小可行材料；贡献写成条件句。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **下游**：**pa-literature-mapper**（把竞争解释放回文献）、**pa-concept-mechanism-builder**。

### pa-literature-mapper：文献解释地图

- **定位**：按解释变量、机制、前提与证据给文献分组，写出可检验的精确缺口，并核验引用。
- **什么时候触发**：写文献综述或理论综述；需要梳理竞争解释；要核实一批书目与引文是否真实、是否支持论断。
- **关键纪律**：记录检索式、日期、数据库与纳排依据，没有做系统检索就称为范围性梳理；书目是否真实与原文是否支持论断是两次检查；找不到的条目放进未核实清单，不混入参考文献；区分「文献遗漏了 M」与「本次检索尚未发现 M」。
- **产出**：检索范围与限制、解释路径比较表、关键分歧、精确缺口、引用核验表、短综述。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **上下游**：上游 **pa-question-framer**；下游 **pa-intro-drafter**、**pa-section-writer**（文献节）。

### pa-concept-mechanism-builder：概念与机制

- **定位**：检验概念创新是否成立，把机制写成可观察的步骤。
- **什么时候触发**：提出「X 治理」「X 型政府」之类的新概念；画了分析框架但箭头说不清；审稿人说机制是黑箱。
- **关键纪律**：概念要有最小必要属性、正例、非例与边界案例，并与最接近的既有概念逐维比较；删掉新名称后若没有新增解释，就沿用旧概念；机制写成「制度条件 → 行动者目标与约束 → 策略 → 互动 → 中间过程 → 结果」，逐条箭头记录理由、时间顺序、证据与最强替代机制；统计中介或受访者的解释不等于机制已被证实。
- **产出**：概念卡与相邻概念比较表、机制链与箭头证据表、适用边界，以及最薄弱的一条箭头和最省力的补证办法。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **上下游**：上游 **pa-question-framer**；下游 **pa-research-design**、**pa-paper-architect**。

### pa-theory-localizer：理论适用性与本土化

- **定位**：说清制度条件究竟改变了一个理论的什么。
- **什么时候触发**：稿件里出现「西方理论无法解释中国」「基于中国情境拓展」「丰富了 X 理论」，但说不清改了什么。
- **关键纪律**：先公平还原原理论，不拿简化版当靶子；把「中国情境」拆成权责配置、干部责任、财政关系、组织边界、政策试验、信息结构等可比较的制度条件；修正类型只有边界修正、关系变化、机制增补或替代、概念重构，也允许结论是「现有理论已能解释」；写成可在其他地区或时期检验的条件命题。
- **产出**：原理论及出处 → 条件变化 → 原预测与新预测 → 区分证据 → 修正类型与边界；一条与证据强度匹配的贡献句，一条需要删弱的夸大句。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **下游**：**pa-research-design**、**pa-paper-architect**。

### pa-research-design：研究设计

- **定位**：让案例选择、过程追踪、定量识别或混合方法真正服务于研究问题。
- **什么时候触发**：选案例、做变量操作化、设计访谈提纲、担心识别问题、不知道混合方法里两种材料各干什么。
- **关键纪律**：先写出核心主张与至少一个竞争解释，以及什么观察能区分二者；便于进入不等于理论选样；同一访谈的多句话不等于多源证据；前趋势不显著不证明平行趋势，稳健性检验修不了根本的识别缺陷；尚未开展的访谈、数据收集与分析一律写成计划。方法文献从已核验的出处清单中取，不凭记忆补作者与页码。
- **产出**：主张—证据表、样本或案例方案、操作化或访谈提纲、主要威胁与补救、最小可行设计。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **上下游**：上游 **pa-concept-mechanism-builder**、**pa-theory-localizer**；下游 **pa-paper-architect**、**pa-section-writer**（设计节）。

### pa-paper-architect：论文架构（公共管理论文的「八股」）

- **定位**：按论文体裁规划全文结构，并说明每一节为什么放在那个位置。
- **什么时候触发**：「按八股帮我搭框架」「章节怎么排」「材料都有了，怎么组织成一篇论文」。
- **关键纪律**：「八股」是读者依次要问的问题，不是六个固定标题；先判断论文目标（解释机制、估计效应、构造概念、规范评价、文献综合、政策设计），保留作者已有的合理结构；每一节写清回答哪个问题、承接哪个前提、主张与证据、交给下一节什么；没有结果只能给计划骨架。
- **产出**：带理由的全文框架、关键节的段落规划、现有材料与各节的对应及缺口。
- **对应 handbook**：[03 写作架构](../handbook/03-writing-architecture.md)
- **上下游**：上游 **pa-research-design**；下游 **pa-intro-drafter**、**pa-section-writer**；需要深入因果检查时接 **pa-argument-architect**。

### pa-argument-architect：因果链与论证链

- **定位**：同时搭两条链：世界中的因果链（条件怎样改变行动者选择、互动与结果），文本中的论证链（读者为什么应接受主张，每部分消除哪个疑问）。
- **什么时候触发**：「这段因果站得住吗」「为什么要这样写」「段落之间接不上」「把主张拆成可检验的子问题」。
- **关键纪律**：结构不是证据（「因为先写了文献，所以机制成立」），顺序不是因果（「A 发生后 B 发生」）；在论文、章节、段落、句子四层上检查，向下拆前提、向上合证据；区分描述、相关、机制一致性、因果效应与条件性推广；局部改稿时在内部检查，交付干净正文，不在论文里塞教学标签。
- **产出**：嵌套大纲或修订稿；需要时附「上级问题｜本层主张｜证据｜推理桥梁｜替代解释｜强度与边界｜为什么在这里写」表；最关键的断点与两种修复（补证据或降主张）。
- **对应 handbook**：[03 写作架构](../handbook/03-writing-architecture.md)
- **用法特点**：横向技能，写作的任何阶段都可以调用。

### pa-intro-drafter：引言写作

- **定位**：围绕论文的论证链写出或重构引言。
- **什么时候触发**：写引言、重构导论、压缩政策背景，或把问题、文献、设计与贡献连成一个完整的开篇。
- **关键纪律**：背景只留解释研究问题所需的信息；文献按解释路径分组；不把「研究较少」当缺口，没有完成检索不写「首次」；只有完成的研究才报告发现；贡献逐项对应缺口，新场景、新算法、政策重要性都不自动等于理论贡献；所有具体事实、数字、观点都要能追溯到材料或已核验来源。
- **产出**：连贯的引言正文，正文之外简列证据缺口；材料不足时写完能写的部分并附骨架。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md) · [03 写作架构](../handbook/03-writing-architecture.md)
- **上下游**：上游 **pa-paper-architect**；下游 **pa-section-writer**、**pa-title-abstract**。

### pa-section-writer：正文写作

- **定位**：撰写或重构文献回顾、理论框架、研究设计、案例分析、实证结果、讨论与结论。
- **什么时候触发**：「帮我写理论框架这一节」「案例分析写成了流水账」「讨论只是在重复结果」。
- **关键纪律**：先定位这一节对主论证的作用；段落按「主张 → 材料 → 推理 → 限定」组织，但不强求固定句式；分析节把事实叙述与解释分开，呈现反例与竞争解释；政策建议写明对应的机制、实施条件与代价；不用虚构的案例、引文、统计值或访谈填篇幅；只要一节时不重写整篇。
- **产出**：可直接使用的正文，外加未解决的证据缺口与对主张强度的调整。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **上下游**：上游 **pa-paper-architect**、**pa-intro-drafter**；下游 **pa-prose-polisher**、**pa-paper-reviewer**。

### pa-title-abstract：题目、摘要与关键词

- **定位**：从成稿中写出忠实的题目、摘要与关键词。
- **什么时候触发**：要题目备选、压缩投稿摘要、写中英文摘要。
- **关键纪律**：摘要里的每个主张都能指回正文，没有结果就不写成「已完成研究」的摘要；题目给少量差异明确的方案（问题导向、机制导向、对象导向），副标题用来限定材料或案例；中英文保持研究范围、因果强度与数值一致；有字数限制时实际计数并说明口径。
- **产出**：首选题目与必要的备选、摘要、关键词，以及仍需确认的信息。
- **对应 handbook**：[03 写作架构](../handbook/03-writing-architecture.md)
- **上游**：**pa-intro-drafter**、**pa-section-writer**。

### pa-prose-polisher：中文学术语体润色

- **定位**：在不改变证据、论点与引用含义的前提下，把话说清楚。
- **什么时候触发**：「帮我润色这段」「去掉 AI 味」「太公文腔了」「句子太长」。
- **关键纪律**：保留论点、因果强度、概念、事实、数值、引用指向与作者立场；优先修主语缺失、名词堆叠、长串递进、指代不明与空泛评价；不把「相关」升为「导致」，不把局部观察扩成普遍规律；不为「降 AI 味」加错字或编造个人经历；发现逻辑问题在正文外提示，但照样完成用户要求的语言修改；不承诺检测器分数。
- **产出**：润色后的完整文本，另列实质调整。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **上下游**：上游 **pa-section-writer**；发现结构问题时转 **pa-paper-reviewer**。

### pa-paper-reviewer：投稿前结构审稿

- **定位**：先审文章成不成立，再审写得顺不顺。
- **什么时候触发**：投稿前自查；想要一份像审稿意见一样的结构诊断。
- **关键纪律**：先说明实际审阅的范围，只看摘要不能判定全文缺什么；按论文类型评价，不对规范研究和综述要求因果识别；每条问题给出原文位置、缺陷编码、严重度、为什么影响核心主张、改法与验收条件；区分「没有呈现」「尚未核验」「证据相反」；不推断作者动机，不预测录用概率。
- **产出**：一句话复述文章最强的可辩护主张、至多三个最高优先级的问题、分维度诊断、按依赖排序的修改计划、需补证据与需降格的主张。
- **对应 handbook**：[01 论文逻辑](../handbook/01-chinese-pa-paper-logic.md)
- **上下游**：诊断出的问题按缺陷编码转交对应技能；需要多视角时接 **pa-supervisor-panel**。

### pa-supervisor-panel：导师组会诊

- **定位**：用七个研究镜头（制度逻辑、概念工程、多目标治理、政策过程、改革次序、理论适用、执行博弈）分别诊断，再合并成一份修改计划。
- **什么时候触发**：「请几个导师视角一起看」「检查这篇的承重问题」「比较几种解释路径」。
- **关键纪律**：镜头是研究动作，不代表任何真实学者发言；按稿件类型选用相关镜头，不适用的说明原因，不硬造问题；每个镜头给出稿件锚点、关键诊断、一项具体修改、所需证据与适用边界；意见冲突时说明各自依赖的假设，按稿件主类型裁决，不投票；镜头卡只加载已验证的规则。
- **产出**：共同指向的一个承重问题、至多五项按依赖排序的修改及验收条件、重写后的「研究问题 → 机制或规范推理 → 证据 → 贡献」四行骨架。
- **对应 handbook**：[02 蒸馏协议](../handbook/02-distillation-protocol.md)（镜头从何而来）
- **上游**：**pa-paper-reviewer**。

### pa-journal-fit：选刊与投稿适配

- **定位**：依据期刊官网范围、当前投稿指南与近期真实刊文，比较稿件与目标期刊的适配度。
- **什么时候触发**：选刊、比较几本目标期刊、按期刊读者调整论文定位、核对投稿规范。
- **关键纪律**：记录访问日期与链接；无法联网时只基于用户提供的资料比较，并写明哪些要求未核验；第三方经验只作检索线索；不为迎合期刊改变事实或夸大贡献；不承诺分区、收录、审稿周期或录用；选刊不等于授权投稿。
- **产出**：候选期刊比较表（适配理由、主要差距、所需修改、官方要求与核验状态）、首选与备选的依据。
- **上下游**：上游 **pa-paper-reviewer**；下游 **pa-revision-responder**。

### pa-revision-responder：退修与逐条回复

- **定位**：把审稿意见变成可追踪的修改和逐条回复。
- **什么时候触发**：收到退修意见，要写修改说明、回复信或修改计划。
- **关键纪律**：保留编辑与各审稿人的原编号，把复合意见拆成子项，不合并掉不好回答的问题；先建「意见—判断—行动—修改位置—验收条件」矩阵；区分接受、部分接受、澄清、基于证据的不同意；先完成修改再写「已修改」，没做的分析写成计划或说明限制；输出供作者审阅，不自动发给编辑。
- **产出**：退修优先级、逐条回复、真实的修改位置、尚未解决的事项。
- **上游**：**pa-journal-fit**、**pa-paper-reviewer**。

### pa-scholar-distiller：研究动作蒸馏

- **定位**：从经核验的论文或获准分析的匿名导师批注中，蒸馏出可检验的研究动作规则。
- **什么时候触发**：做论文结构标注、导师经验提炼、规则支持度统计或留出验证。
- **关键纪律**：书目核验、读过全文、标注正确、规则有效是四件不同的事；每条标注附短原文摘录与段落位置；形成规则时看过的论文不进入留出集；同一个模型重复调用不等于独立复核；机器统计不自动修改规则状态；不模仿学者口吻。
- **产出**：语料与缺失报告、可复查的标注、候选规则及反例、支持度与一致性和评测状态、下一步最小补证方案。
- **对应 handbook**：[02 蒸馏协议](../handbook/02-distillation-protocol.md)；批量命令见仓库的 [distill/README.md](../distill/README.md)
- **用法特点**：给维护者和研究者用；完整流程需要整个仓库，而不只是这个技能目录。

## 怎么用这些技能

### 安装为 Agent Skills（推荐）

按顶层 README 的[快速开始](../README.md#快速开始-quick-start)装好之后，用自然语言即可触发，不需要记命令。下面这类说法会命中对应技能：

- 「这个题能不能写成公共管理论文？下一步做什么？」→ `pa-router`
- 「帮我把这个选题提炼成研究问题 / 问题意识不强怎么改」→ `pa-question-framer`
- 「帮我梳理文献、找研究缺口 / 核实这些参考文献」→ `pa-literature-mapper`
- 「我提了一个新概念，帮我看站不站得住 / 帮我画机制链」→ `pa-concept-mechanism-builder`
- 「我用的是西方理论，怎么写出中国情境的贡献」→ `pa-theory-localizer`
- 「帮我设计案例选择 / 这个 DID 有什么识别问题」→ `pa-research-design`
- 「按公共管理论文的八股帮我搭框架」→ `pa-paper-architect`
- 「这段因果论证有没有跳步 / 为什么要这样写」→ `pa-argument-architect`
- 「帮我写引言」→ `pa-intro-drafter`
- 「帮我写理论框架 / 案例分析 / 讨论这一节」→ `pa-section-writer`
- 「帮我起几个题目 / 压缩摘要 / 写英文摘要」→ `pa-title-abstract`
- 「帮我润色 / 去掉公文腔和 AI 味」→ `pa-prose-polisher`
- 「投稿前帮我审一遍」→ `pa-paper-reviewer`
- 「请几个导师视角一起会诊」→ `pa-supervisor-panel`
- 「这篇适合投哪本刊」→ `pa-journal-fit`
- 「这是审稿意见，帮我写修改说明」→ `pa-revision-responder`
- 「帮我标注这篇论文的研究动作 / 从导师批注里提炼规则」→ `pa-scholar-distiller`

### 显式调用

想确保用到某个技能时，可以直接点名：在 Claude Code 中输入 `/pa-paper-reviewer`，或者在任何工具里说「用 pa-paper-reviewer 技能审这篇稿子」。其他工具的调用方式以其文档为准。

### 不安装也能用

每个 `SKILL.md` 本身就是一份结构化的思考清单：

- 把它贴进任何 AI 助手（Claude、GPT、DeepSeek、Qwen、Kimi 等）当作系统提示词；需要细节时，再把同一目录下 `references/` 里的相关文件一起贴进去；
- 或者把它当作静态检查清单，不借助任何 AI，逐条对照自己的稿子。

### 关于镜头卡与规则状态

`pa-supervisor-panel`、`pa-paper-architect`、`pa-argument-architect` 会读取由规则登记表生成的镜头卡。镜头卡**只收录已验证（validated）的规则**；目前所有规则仍是种子假设，所以卡中暂时只有每个镜头的关注点与追问，这些是启发式检查。想查看全部种子规则及其来源，读仓库的 [rules/preview/lens-cards-preview.md](../rules/preview/lens-cards-preview.md)。如果你愿意在验证完成前就使用种子规则，可以修改 `rules/registry.yaml` 中的 `runtime_statuses` 后运行 `python scripts/build_refs.py --write`，但要清楚这些规则尚未经过验证。
