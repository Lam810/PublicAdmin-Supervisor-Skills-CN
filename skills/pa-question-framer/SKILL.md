# PA Question Framer

## Core belief
公共行政论文最危险的状态是“有题目，没有问题”。

“数字政府对基层治理的影响”“研究政务大模型”“分析共同富裕政策”都只是主题。

## Procedure

### Step 1 — Extract the phenomenon
用一句无评价、可观察的话写出现象。不要使用“赋能、重塑、促进、高质量”等预设结论词。

### Step 2 — Write the default expectation
如果按既有理论/常识，本来应该发生什么？

### Step 3 — Locate the mismatch
寻找至少一种：
- **反常**：现实与理论预期相反；
- **并存**：两个看似冲突的结果同时存在；
- **异质性**：同一制度在不同地方/组织/时期效果不同；
- **转变**：机制在某个时间点发生结构性变化；
- **稳定谜题**：正式制度不断变化，但某种行为长期稳定；
- **黑箱**：已知 X 与 Y 相关，但中间过程不清楚。

### Step 4 — Name the theoretical target
问题最终想改变什么？
- 一个理论边界；
- 一个因果机制；
- 一个核心概念；
- 一类治理关系；
- 一个政策过程模型。

### Step 5 — Generate the RQ
优先使用：
- 为什么在 X 条件下，A 反而导致 B？
- A 与 B 看似冲突，为何能够同时成立？
- 同一制度 A 为何在 C1 与 C2 中产生不同结果？
- 从 T1 到 T2，A 的治理机制为何由 M1 转向 M2？
- X 如何通过 M 改变 Y，且这一机制何时失效？

避免：
- X 的现状、问题及对策是什么？
- X 是否促进 Y？
- 如何推动 X 高质量发展？

### Step 6 — Test publishability
一个合格问题至少满足 4/5：
- 不知道答案也能成立；
- 不是政策文件原句换问号；
- 能与至少一组既有解释发生冲突；
- 有可获得材料能区分竞争解释；
- 答案能改变某种一般认识，而不只描述一个地方。

## Output
1. Topic
2. Observable phenomenon
3. Default expectation
4. Puzzle
5. Research question
6. Theoretical target
7. Two competing explanations
8. Minimum evidence needed
9. One-sentence contribution if the mechanism is supported
