# 因果与嵌套论证架构

先读 [四层论证与因果检查](references/nested-argument.md)，需示范时读 [虚构拆解示例](references/worked-example.md)。
研究设计部分如何写出识别威胁、对照检验与设计定位，参见 [写作架构卡](references/writing-architecture.md)。

同时搭建两条不同的链：
- 世界中的因果链：条件怎样改变行动者选择、互动及结果。
- 文本中的论证链：读者为什么应接受主张，每部分如何消除一个疑问。

“因为先写文献，所以机制成立”把结构当证据；“事情A后发生B”把顺序当因果，两者都要拆开。

## 四层嵌套

1. 论文层：一句主问题、一个可辩护回答、必要子命题及反证条件。
2. 章节层：每节回答哪个子问题、依赖前节确立什么、产出什么供后节使用。
3. 段落层：每段只承担可辨识的主张，以证据和推理桥接到上级子命题；一段可以包含限定或反驳。
4. 句子层：识别陈述、证据、推论、限制或过渡功能。不给每句硬贴标签，只标影响论证的跳步。

用户只要求局部改稿时在内部完成检查，交付干净正文；用户问“为什么这样写”时展示相应层次的理由。不能在最终论文里塞满教学标签。

## 两遍检查

向下拆：主结论需要哪些前提，每个前提如何观察或论证？
向上合：各证据最多支持什么，子命题合起来是否足以支持主结论？
若删掉某段后推理不受影响，检查其是否承担必要背景、定义或边界；确实没有作用才删。
对关键箭头追问为什么，追到可观察的行动机制或明确理论前提即止，避免无尽回归。

## 因果强度

区分描述、相关、机制一致性、因果效应、条件性推广。理由充分不等于效应已识别，识别出总效应不等于中间机制已确认。
检查共同原因、反向因果、选择进入、时间顺序、测量和层级跳跃。比较最强替代解释及不应出现的结果。
规范论文使用“价值前提—理由—反对意见—裁决”，不要伪造经验因果。

## 交付

按任务规模输出嵌套大纲或修订稿；需要解释时附表：
上级问题｜本层主张｜证据／理由｜推理桥梁｜替代解释｜强度／边界｜为什么在这里写。
最后给最关键的断点、两种修复途径（补证据或降主张）与验收标准。
